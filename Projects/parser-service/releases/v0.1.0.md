## 1. TL;DR

First shippable version of parser-service: the consumer half of the AIOZ Map pipeline. It
subscribes to crawler-service's RabbitMQ raw-document events, parses and normalizes them
into Postgres, and serves the result to the map frontend through a gated REST API (~70
read endpoints), plus user accounts, API keys, dashboard layouts, and alerts. Ships as two
binaries: `cmd/server` (API) and `cmd/consumer` (worker pool).

---

## 2. Highlights

### Event-driven parse pipeline

- `cmd/consumer` consumes `process-data.*.raw-data.available` from RabbitMQ
  (`internal/queue`), routes each message by source to a registered handler
  (`internal/worker/registry.go`), retries with exponential backoff
  (`worker/retry.go`, `WORKER_RETRY_BASE_DELAY`/`WORKER_RETRY_MAX_DELAY`), and parks
  poison messages on a dead-letter queue (`internal/queue/dlq.go`).
- 20 handlers registered in `internal/app/process.go`: earthquake (USGS, EMSC, GDACS,
  ShakeMap), volcano (USGS, Smithsonian GVP, VolcanoDiscovery RSS, AviationWeather
  IS-SIGMET VA), fire (FIRMS, active-fire FIRMS/Copernicus, GWIS ECMWF/Meteo-France/NASA),
  drought (USDM), tsunami (NOAA), weather datasets, aircraft states (OpenSky), and
  airports (OurAirports).
- Idempotency is enforced at the DB layer via a `processed_events` table
  (`internal/database/processed_events.go`), so redelivery does not duplicate rows.

### Map + weather read API

- `cmd/server` exposes ~70 `GET` endpoints under `/api/v1` (`internal/api/router.go`)
  spanning weather, marine, wind, forecast, air pollution/quality, drought, water,
  reservoir storage, snow cover, sea ice, coral reef watch, atmospheric CO2/CH4/N2O/SF6,
  tides, sun/moon, landslide, earthquake, volcano, volcanic ash, severe weather,
  tsunami, tropical cyclone, FIRMS fire, and space weather.
- Every group sits behind a runtime feature gate (`api.disabled` + `api.allowed` in
  config). Gated-off routes are not registered at all, and the served Swagger document is
  filtered to match, so `/swagger` never advertises a path the deployment does not have.

### Flight tracking and the aircraft detail panel

- Live positions: `GET /api/v1/aircraft/states/bbox` (bounding box; `limit=-1` returns all)
  and `/states/:icao24`, fed by the OpenSky consumer into `flight_occurrence_positions`.
- `GET /api/v1/aircraft/:icao24` serves the detail panel: aircraft record, operator, and
  recent flights, assembled in `internal/api/aircraft/service.go`.
- Upstream calls are rate-limit-aware and cache-backed directly in the flight tables, with
  fresh/stale TTL tiers (detail 7d fresh / 30d stale; flights 8h fresh / 3d stale). When
  the provider is throttled or down, the endpoint serves stale data rather than failing;
  only a miss with no stale row at all returns an error.
- Schema in `migrations/002_flight_tracking_schema` (airlines, airports, aircraft,
  aircraft_operator_history, flight occurrences/positions/paths) and
  `003_aircraft_detail_cache` (`aircraft.icao_code`).

### Accounts, API keys, layouts, and alerts

- Auth (`internal/api/auth`): email/password signup with OTP verification, sign-in,
  refresh tokens, logout, password change, forgot-password reset flow, email change with
  verification, and MetaMask wallet challenge/verify plus link/unlink. HTML email
  templates live in `templates/`.
- API keys (`/api/v1/api-keys`, alias `/apikey`): create, list, get, delete - all
  authenticated.
- Dashboard layouts (`/api/v1/dashboard-layouts`, alias `/layout`): full CRUD plus rename.
- Alerts (`/api/v1/alert`): CRUD plus a background chore (`alert.chore_disabled` gate) and
  an outbox table (`internal/database/alert_outbox.go`) that evaluates incoming hazard
  events against user-defined alert rules.

### gRPC to producer, and observability

- gRPC client to crawler-service (`internal/utils/grpc`, `grpc.producer_addr`) for
  weather point/grid values, aircraft flights, and aircraft detail, with a shared
  interceptor.
- `/healthz` and `/ping` liveness endpoints, Prometheus middleware
  (`internal/pkg/middleware/prometheus.go`), a debug listener on `server.debug_addr`, and
  a build-info package (`internal/version`) carrying version, commit, build time, and CI
  pipeline ID via linker flags.

## 3. Added

- **`internal/config`** - full Viper-based config with env-var override; `config.example.yaml`
  and `.env.example` document every key.
- **`internal/utils/geojson`** - country/province/district/basin GeoJSON lookup used to
  attach admin regions to hazard events (`make geojson-gen`, `make geojson-db-up`).
- **`internal/pkg/lrucache`** - in-process LRU used by hot read paths.
- **`internal/utils/ai_service`** - A2A (`a2aproject/a2a-go`) client with per-agent client
  caching.
- **`internal/api/map_extract`** - `/weather/value`, `/value/snapshots`, `/dataset/forecast`
  proxied to the map-extract service, with an optional cron-scheduled weather value
  snapshot job (`map_extract.weather_value_snapshot`).
- **`mock-data/`** - ~90 upstream fixture payloads plus a mock server, so handlers can be
  exercised without live providers.
- **Docs** - generated Swagger (`docs/`, `make swagger`), `docs/TEST_CASES.md`,
  `docs/LINTING.md`, `DATASOURCE_MIGRATION_PLAN.md`, `weather_dataset_plan.md`.

## 5. Fixed

Pre-release fixes, listed for traceability rather than as user-visible regressions:

- **`aircraft`** - the aircraft detail cache moved out of a standalone
  `aircraft-flight-cache` table into the flight tables themselves; the interim table and
  the four commits building on it were reverted before release, so v0.1.0 ships only the
  flight-table design.
- **`firms`** - wildfire results are filtered, so the fire layer no longer returns
  non-wildfire detections.
- **`weather`** - map layer selection and the OpenWeatherMap image naming were corrected;
  Open-Meteo forecast metadata is now populated.
- **`app`** - service startup uses `errgroup` instead of a bare `WaitGroup`, so a failing
  component aborts startup instead of hanging.
- **`reservoir_storage` / `snow_cover`** - date handling corrected for both services.

## 6. Migration notes

- **Database** - run `make migrate-up` before starting either binary. Three migrations
  apply on a fresh database: `001_baseline_schema`, `002_flight_tracking_schema`,
  `003_aircraft_detail_cache`.
- **Config** - copy `config.example.yaml` and fill in the secrets that ship empty:
  `token.*_private_key` / `*_public_key` (JWT keypairs), `mail.key` (Resend),
  `admin.api_token`, `database.url`, `air_pollution.api_key`, `wwo.api_key`,
  `worldtides.api_key`, `map_extract.base_url`, `grpc.producer_addr`.
- **Feature gates default to closed.** `api.disabled: true` and `broker.disabled: true` in
  the example config mean only the entries listed under `api.allowed` /
  `broker.allowed_event_types` are wired up. Add every datasource key the deployment needs
  or its endpoints will 404 and its events will be ignored. `alert.chore_disabled: true`
  likewise keeps the alert chore off until explicitly enabled.
- **RabbitMQ** - the DLX/DLQ (`crawler-svc.events.dlx`,
  `process-data.dev.raw-data.available.dlq`) must exist or be declarable by the service
  user; adjust the `dev` segment of the queue names per environment.
- **crawler-service** - parser-service is downstream of it. Both the RabbitMQ event stream
  and the gRPC producer (`grpc.producer_addr`, default port 50052) must be reachable, or
  the map serves only what is already in Postgres.
- **GeoJSON files** - `paths.*_geojson_path` must point at readable files inside the
  container (`/app/data/geojson` in the shipped images); hazard region tagging fails
  without them.
- **Private Go module** - builds pull `gitlab.internal/tuan.quang.tran/aioz-log`. CI uses a
  job token and BuildKit secrets; local builds need `GOPRIVATE`/`GOINSECURE` and an
  ssh-agent key.
