# Release review v0.1.0

Reviewed 2026-09-07. Scope: the release-critical surface only - `internal/api/router.go`,
`internal/api/aircraft`, `internal/app`, over the aircraft-detail-panel branch
(`5b8d6cb..243316b`). The full v0.1.0 range is the entire repository history (566 files,
101k insertions), which is not reviewable in one pass; the rest of the tree was reviewed
incrementally during development.

Build and `go test ./internal/api/aircraft/...` pass. Route registration was verified
empirically: gin 1.12 does not panic on `/aircraft/:icao24` coexisting with
`/aircraft/states/bbox`.

**Verdict: fix-first.** One finding (F1) can prevent flight data from ever persisting on
a non-UTC database server, and two more (F2, F3) let an unauthenticated caller drive paid
upstream calls and unbounded table scans. Everything below F3 can ship and be fixed in
v0.1.1.

---

## Blocking

### F1 - `internal/api/aircraft/store.go:368` - `flight_date` DATE compared against a `timestamptz`

`flight_date` is `DATE NOT NULL` (migration 002, line 116), but the re-read binds a Go
`time.Time` at UTC midnight: `Where("flight_id = ? AND flight_date = ?", flightID,
occurrence.FlightDate)`. Postgres resolves `date = timestamptz` by converting the date to a
timestamptz at midnight **in the session time zone**, and nothing in the DSN or
`database.Connect` pins `TimeZone`. On any server whose `timezone` GUC is not UTC the
equality never matches, `First` returns `ErrRecordNotFound`, and the transaction fails with
"reread flight occurrence" - so no flight occurrence is ever persisted, which in turn keeps
`LastFlightsSyncAt` nil forever and defeats the flight cache entirely. The same skew shifts
the `flight_date BETWEEN ? AND ?` windows in `ListRecentFlights` (line 552) and
`LastFlightsSyncAt` (line 577) by a day.

**Fix:** compare against a value normalized for a `date` column, or cast explicitly. Pin
`TimeZone=UTC` in the DSN as a belt-and-braces measure.

### F2 - `internal/api/aircraft/service.go:113` - nil position bypasses the staleness gate; DB errors swallowed

`if pos, err := s.store.GetLatestByICAO24(...); err == nil { position = pos }` leaves
`position == nil` on any error, and the 404 gate below is guarded by `position != nil`. An
icao24 that has never been seen, whose ping rows were pruned, or that hit a DB error skips
the "landed / signal lost" rejection and falls through to `resolveAircraftDetail` +
`resolveAircraftFlights` - two paid AeroDataBox gRPC calls. `/api/v1` has no middleware
(`router.go:110`), so an anonymous caller can walk arbitrary 6-hex strings and force one
upstream fetch pair per request, each cached as a row in `aircraft`.

**Fix:** drop the `position != nil &&` guard - `isPositionStale(nil, now)` already returns
`true`. Log the DB error instead of discarding it.

### F3 - `internal/api/aircraft/endpoint.go:85` - `limit=-1` is an unbounded unauthenticated full-table read

The new sentinel skips the `MaximumLimit` clamp, and `findLatestByBBox` (`store.go:85`)
applies `Limit` only when `q.Limit > 0`, so the query runs with no `LIMIT`. A whole-globe
bbox on the public `/api/v1` group materializes every distinct aircraft's latest position
into `[]AircraftStateDTO` and serializes it.

**Fix:** gate behind auth or replace "unbounded" with a high hard ceiling.

## Non-blocking

### F4 - `internal/api/aircraft/service.go:255` - singleflight captures the first caller's context

`s.detailGroup.Do(icao24, func() { return aircraftdetailclient.GetAircraftDetail(ctx, ...) })`
(and `fetchFlights` at line 335) closes over the ctx of whichever request started the call.
If that client disconnects, the shared gRPC call aborts with `codes.Canceled` and every
other waiter gets a 502 "Temporarily unavailable" via `fetchFailureError`'s default branch.
**Fix:** use a detached context (`context.WithoutCancel` plus the interceptor timeout)
inside the singleflight function.

### F5 - `internal/api/aircraft/service.go:290` - transient `ListRecentFlights` error returns an empty history

On error `cached` becomes nil, but `lastSync` is fetched independently. If
`LastFlightsSyncAt` succeeds and is within `flightsFreshTTL`, line 301 returns nil as the
answer - the panel renders zero flights though upstream was never consulted.
**Fix:** a read failure should force the refetch path, not be treated as "fresh and empty".

### F6 - `internal/api/aircraft/service.go:301` - negative results are never cached

`LastFlightsSyncAt` derives freshness from `MAX(flight_occurrences.updated_at)`. When
upstream returns an empty flight list - common for general aviation - no occurrence rows are
written, `lastSync` stays nil forever, and the fresh check can never be true. The 8-hour TTL
never applies for those aircraft and every request goes upstream, which is the exact
rate-limit and cost problem the cache exists to prevent.
**Fix:** record a negative-cache marker for empty results.

### F7 - `internal/api/aircraft/service.go:194` - a DB write failure discards a good upstream response

When `UpsertAircraftDetail` fails the code returns `cached, nil` and throws away `detail`,
which it already holds. If `cached` is also nil this returns `(nil, nil)`, so
`resolveAircraftFlights` takes the `aircraft == nil` branch (line 281) and skips persisting
the fetched flights too - one transient DB error costs both caches.
**Fix:** serve the fetched `detail` even when the write fails.

### F8 - `internal/api/aircraft/service.go:384` - `isInProgressStatus` has no upper age bound

Anything that is not `Arrived`/`Cancelled`/`Canceled` counts as in progress, including
`Diverted`, `Unknown`, and any status upstream stops updating. Combined with the
`!dep.After(now)` check over a 7-day window, a flight that departed six days ago can be
selected as "current"; `applyDerivedScheduleStatus` then renders `time_since_departure` as
e.g. `"148:22 ago"` and computes distance/ETA against that destination.
**Fix:** bound the candidate to a plausible flight duration, or to today.

### F9 - `internal/api/aircraft/store.go:382` - `findOrCreateFlight` under-keys the `flights` row

The lookup is `flight_number` + `departure_airport_id` + `arrival_airport_id` only - airline
is not part of the key, and `lookupAirportID` (line 413) returns nil whenever the ICAO code
is absent from `airports`. `airports` is populated solely by the new OurAirports consumer,
so before that feed lands every flight resolves both airport IDs to NULL and all flights
sharing a number collapse into one `flights` row. Since `flight_occurrences` is unique on
`(flight_id, flight_date)`, a same-day outbound and return under one number overwrite each
other, `tx.Save(&f)` rewrites the shared row's callsign/airline/great-circle distance, and
`linkPositions` attaches that day's pings to whichever occurrence survived.
**Fix:** include airline in the key, and do not treat a NULL airport ID as a match.

### F10 - `internal/api/aircraft/store.go:157` - `tx.Save(&record)` blanks columns the payload omits

`aircraftFromDetail` builds a fresh struct with `FirstFlightDate` and `DeliveryDate` always
nil, and `AirlineID` nil whenever `detail.AirlineName` is empty. `Save` writes every column
on the update path, so a refresh where upstream omits the operator wipes a previously stored
`airline_id`.
**Fix:** use `Updates` with a selected column set, or preserve existing values.

### F11 - `internal/app/server.go:116` - both new gRPC clients dial the producer address

`aircraftdetailclient` and `aircraftflightsclient` document themselves as "served by
crawler-service" but are wired to `producerConn.Conn()` (`cfg.GRPC.ProducerAddr`), and
`GRPCConfig` has no second address. If crawler-service is not co-located behind that
address, every panel request gets `codes.Unimplemented` -> 502. Secondary: these are
package-level globals holding a connection that `Connection.Close()` shuts down at graceful
shutdown.
**Fix:** confirm the co-location is intentional; otherwise add a second address key.

### F12 - `internal/api/aircraft/dto.go:366` - `distance_flown_km` can go negative

`flown = great_circle_distance_km - remaining`, where `remaining` is measured from the live
position to the arrival airport. For a holding pattern, a diversion, or a ping predating a
route change, `remaining` exceeds the great-circle distance and the panel publishes a
negative kilometre figure.
**Fix:** clamp at 0.
