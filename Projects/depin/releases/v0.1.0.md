## 1. TL;DR

The first release where the network pays for itself in both directions: client billing
periods close on their own and unpaid accounts are refused, while workers can see their
balance and ask to be paid in AIOZ from the node CLI. Repair became a real subsystem
with its own queue server, `relay` and `jobq` are now standalone binaries, and the whole
thing is built and published by a reproducible multi-platform release pipeline.

Nine migrations (`000041`-`000049`), one renumbered (`000033` -> `000040`), a breaking
`keytool` CLI change, and a load-bearing `go-sdk` pin. Read §6 before you deploy.

⚠️ The diff review for this tag is in [`v0.1.0-review.md`](v0.1.0-review.md) and its
verdict is **fix-first**. Two of its blocking findings are inert only because the
features are off by default: do **not** set `repair.enabled=true` or
`payout.auto-settle-enabled=true` on this release.

## 2. Highlights

### Client billing runs without an operator

Monthly periods now close by themselves and non-payment has consequences.

- A period-close chore (`coord/periodclose`) closes each finished month's worker
  paystubs and client invoices in one order, oldest first, with a 72h grace so late
  tallies and settled orders land first. On by default, guarded by a first-run floor so
  a fresh deployment cannot retroactively close history.
- An accrual watchdog prices usage mid-period and suspends accounts that go further
  than $5.00 past zero.
- A payment gate (`coord/billing.Gate`) refuses uploads and downloads for suspended
  accounts with a dedicated payment error, off a periodically refreshed snapshot rather
  than a per-request query, and fails open if the refresh fails.
- Where: `coord/periodclose`, `coord/billing`, `internal/billing`
- Surface: `coord period-close status`, `coord billing balances|credit|record-period`,
  config `billing-gate.*`, `period-close.*`, Grafana **coord-billing** dashboard

### Workers can be paid, and can ask to be paid

- New `PayoutService` gRPC API: `GetPayoutBalance`, `RequestWithdrawal`,
  `ListWithdrawals`, `CancelWithdrawal`.
- Worker-side CLI: `worker balance` and `worker withdraw <address>` - one pending
  request at a time, cancellable, amount in USD. (The command help calls the binary
  `aioznode`, which is the application directory name, not the shipped file name.)
- Withdrawals carry a `settling` state so a broadcast payout transaction is never
  double-sent, and small withdrawals (default <= $5.00) can settle automatically without
  an operator.
- USD is converted to AIOZ at settlement, not at request time. `GetAiozPrice` exposes
  the quote; clients are quoted spot while worker payouts use the treasury's blended
  rate, and the compensation ledger freezes the rate at invoice time.
- Where: `coord/payout`, `internal/compensation`, `internal/fx`, `cmd/worker/withdraw.go`
- Surface: `pkg/pb/coord/payout/v1`, `coord compensation withdrawals list|settle|reject`

### Egress accounting is now allocated vs settled

The billing ledger stopped conflating "we issued an order limit" with "the bytes were
actually delivered".

- Egress is recorded in two columns: allocated at manifest issue, settled when the
  worker's order comes back. Invoices bill the settled figure.
- Settlement windows get replay protection, so the same window cannot be counted twice.
- Order settlement enforces a horizon, and a bandwidth reconciliation pass compares the
  two ledgers.
- Transient trust-resolve failures now defer a worker's orders instead of archiving
  them - previously any trust error destroyed a whole hour of unsettled orders.
- Audit orders are recorded rather than silently dropped.
- Order limits carry sealed metadata so egress attributes back to the owning contract.
- Where: `coord/order`, `coord/accounting`, `coord/db`, `pkg/pb/coord/orders/v1`

### Repair has a queue of its own

- `jobq`: an in-memory repair job queue with a full gRPC surface (`Push`, `PushBatch`,
  `Pop`, `Peek`, `Requeue`, `Delete`, `Inspect`, `Len`, `Clean`, `Trim`, `Truncate`,
  `Stat`), selectable as the repair backend instead of Postgres
  (`repair.backend=jobq`). It holds nothing durable - the ranged-loop checker rebuilds
  it each pass.
- Repair gained retry policy with backoff, integrity verification of repaired pieces,
  concurrent recovery, `PUT_REPAIR` accounting, download verification, and correct
  shutdown/trailer/PieceID handling.
- Workers can now declare graceful exit on check-in (`exiting`), so repair moves their
  pieces off while they are still online to serve them and upload selection stops
  placing new pieces on them.
- Where: `coord/jobq`, `coord/repair`, `cmd/jobq`
- Surface: `pkg/pb/coord/jobq/v1`, `repair.backend`, repair Grafana dashboards

### Downloads survive load

- Transparent mid-stream retry and resume, end to end: the SDK retries a dead piece
  stream, and the edge resumes rather than silently truncating a `200`.
- Download-resolve admission control: per-file and per-contract rate limiters, a
  segment-list cache, and a bound on how long the coordinator may spend building one
  manifest. Load shedding surfaces as `503 Service Unavailable` instead of a hang.
- Batched bandwidth allocation and smarter download node selection, plus a configurable
  yamux receive window per stream (a stream cannot exceed `window/RTT`).
- Phase-level download tracing across edge, SDK, worker and relay, correlated by
  download id, plus libp2p resource-manager refusal counters.
- Where: `coord/file`, `coord/order`, `edgeserver`, `pkg/p2putil`
- Surface: config `file.download-rate-*` / `file.download-object-rate-*` /
  `file.download-resolve-timeout` / `file.download-data-*`,
  `worker.server.resource-limits.stream-window`,
  Grafana **download-phases** dashboard

### A real release pipeline

- `docker buildx bake` multi-platform release: signed and attested images to the
  registry plus binaries for linux amd64/arm64/arm, windows, freebsd and native macOS
  amd64/arm64.
- GitLab CI covering lint, test, cross-compile validation, coverage ratchet and
  publication, with a `SKIP_VALIDATION` escape hatch and one test run per SHA.
- `docs/RELEASE.md`: a full release runbook - versioning model, branching, pre-flight
  checklist, rollout, verification, rollback, hotfixes.
- Where: `docker-bake.hcl`, `release.docker-bake.hcl`, `.gitlab-ci.yml`,
  `Makefile.release.mk`, `scripts/release/`

## 3. Added

- **`cmd/segment-verify`** - standalone, read-only, on-demand segment health checker.
  `run range|contracts|read-csv|ranges` for sweeps, `check segment|file|contract` for
  single lookups; writes not-found / retry / problem-piece CSVs that round-trip back in.
- **`cmd/relay`, `cmd/jobq`** - relay and jobq split out of `coord` into their own
  binaries, each with its own identity, config and lifecycle.
- **`cmd/worker`** - `balance` and `withdraw` subcommands.
- **`cmd/coord`** - `period-close status`, `compensation withdrawals list|settle|reject`,
  `billing balances|credit`.
- **`worker-updater`** - SHA-256 verification of downloaded update binaries, with an
  opt-in `--require-checksum` flag to refuse any release that publishes no checksum.
- **`hardwareinfo`** - FreeBSD support.
- **`internal/testplanet`** - boots relay peers and behind-NAT workers, so relayed and
  hole-punched paths are exercised in-process.
- **Grafana** - `coord-billing` and `download-phases` dashboards.

## 4. Changed

- **`keytool`** - **breaking.** No secret is accepted as a flag or positional argument
  any more; payloads come from a file flag or stdin, passwords from `--password-file` or
  a no-echo terminal prompt. Key material now goes to `--secrets-out` or stderr, never
  stdout. Full before/after table in `docs/RELEASE.md`.
- **`coord relay` / `coord jobq`** - removed as subcommands. They inherited coord's
  single `--identity-dir` and so ran with the *coordinator's* identity.
- **`cmd/uplink`** - removed. The Go SDK is the supported client.
- **`worker`** - blobstore and filewalker paths deleted; the worker is hashstore-only.
  Space accounting moved to a `PieceSpaceUsedRepository`.
- **`keytool` / `worker` / `worker-updater`** - the AIOZ chain codec is now confined to
  `keytool` behind an injectable codec, keeping ~130MB of chain dependencies out of the
  worker and updater images. This is also what unblocks 32-bit `linux/arm` builds for
  them; `keytool` keeps the codec and is not shipped for that platform.
- **`edgeserver`** - load shedding returns `503` instead of failing opaquely; truncated
  responses are now detected and aborted rather than served as a successful `200`.
- **Migration `000033_worker_version`** renumbered to `000040_worker_version`.
- **Repair queue** - `repair.backend` defaults to `postgres`; `jobq` is opt-in.

## 5. Fixed

- **`coord/order`** - a whole hour of unsettled orders was archived (destroyed) on *any*
  trust-resolve error, not just an untrusted peer. Orders are now deferred.
- **`grpc`/`server`** - peers did not shut down: gRPC servers were not stopped on
  `Close`, dialed connections were never actually closed (`dial.Conn` embedded a nil
  closer), and a connection accepted before its HTTP/2 preface pinned the server's wait
  group. Adds listener tracking and a forced close after the graceful window.
- **`p2p`** - listener stalls on shutdown.
- **`peertls`** - a peer presenting a short certificate chain panicked the process
  instead of being rejected; all remaining chain-index sites guarded.
- **`identity`** - `PeerCAConfig.Load` panicked on a damaged CA file.
- **`vo`** - `PrivKey.Scan` panicked on the output of `PrivKey.Value`;
  `EncryptedPrivateKey.Value` did not produce a valid `driver.Value`.
- **`jobq`** - an `int32` config field could not bind and panicked every role of the
  binary at `init()`.
- **`worker`** - the gRPC server had no TLS credentials, so peer identity did not work.
- **`cache`** - connection close held the mutex.
- **`du`** - `Statfs_t` type mismatches across Unix variants.
- **`pkg/auth`** - the replay timestamp window was `3600000000000` nanoseconds read as
  seconds and multiplied by `time.Second` again, putting the accepted window at roughly
  114,000 years and overflowing `int32` on 32-bit builds. Now 3600 seconds.
- **Security** - hardcoded Postgres credentials removed, `crypto/rand` used for
  security-sensitive randomness, generated files restricted to `0600`, gosec enabled in
  CI.

## 6. Migration notes

- **Database - apply migrations before any `coord api` replica rolls.** This release
  adds `000041`-`000049`. `coord api` does **not** migrate; only `coord run` and
  `coord core` do. An `api` replica started one migration behind serves the new RPCs and
  fails every call on a missing table. `000045_worker_withdrawals` is the first release
  where this bites: it adds the table the worker-facing payout service reads on every
  request.
- **Migration renumber.** `000033_worker_version` is now `000040_worker_version`. A
  database that already applied the old `000033` needs its `schema_migrations` row
  reconciled by hand before migrating.
- **Do not roll back past `000046` with a withdrawal in `settling`.** That state means a
  payout transaction may already be on chain, so the down migration refuses rather than
  guessing. Resolve each one first - check its `broadcast_tx_hash`, then
  `coord compensation withdrawals settle <id> --receipt <tx>` or `reject <id>`. List
  them with `coord compensation withdrawals list --status settling`.
- **`go-sdk` pin is load-bearing.** Anything building against `aioz-depin/go-sdk` must
  use `v0.0.0-20260821093526-73f0c7097e45` or newer. The SDK unmarshals a download
  manifest into its own `OrderLimit` and re-marshals it toward the worker; an older SDK
  drops the new `encrypted_metadata` fields, the worker sees a limit that no longer
  matches its signature, and **every piece read fails as "signature is not valid"**.
- **Payment enforcement is on by default.** `billing-gate.enabled` and
  `period-close.watchdog.suspend-enabled` both default to `true`. Turning the gate on suspends nobody by itself -
  an account only enters the snapshot once the watchdog decides it is more than $5.00
  past zero. Set `billing-gate.enabled=false` to deploy without enforcement.
- **Automatic period close is on by default**, with a first-run floor: the first pass
  after upgrade closes nothing older than the period in progress unless you set
  `period-close.first-period` (`YYYY-MM`) deliberately. Automatic settlement of small
  withdrawals is **off** by default (`payout.auto-settle-enabled`).
- **`relay` and `jobq` are separate binaries now.** Deploy them as their own processes.
  **Mint one identity per relay host** - never copy an identity between hosts, the peer
  ID is what workers dial. Roll relays one at a time, adding the new multiaddrs to the
  coordinator's `contact.relay-addrs` *alongside* the old ones before switching, or
  every behind-NAT worker drops. Full procedure in `docs/RELEASE.md` §7.
- **Port collision if relay and jobq share a host.** Both default to `:7781`. Change
  jobq's `--server.address` (or the relay's `--p2p-address`) when co-locating them.
- **`keytool` automation must be updated** if it passed a mnemonic, private key, armor
  or password on the command line - see §4 and the `docs/RELEASE.md` appendix. Fleet
  scripts (`dev/fleet/gen-fleet.sh`, `worker-pkg/init.sh`, `dev/rollout-scale-test.sh`)
  are unaffected. An operator who ran `keytool new > key.txt` to keep a seed phrase now
  needs `--secrets-out <path>`.
- **`uplink` is gone.** Move any tooling to the Go SDK or the edge server.
- **Repair remains off by default** (`repair.enabled=false`). Enabling it against a real
  fleet is a separate, deliberate rollout.
- **Optional, off by default:** download phase tracing
  (`worker.storage.detailed-metrics`, `worker.server.resource-limits.trace-blocked`)
  costs a timer per frame served. Enable on the hosts you are measuring, not fleet-wide.

## 7. Internal

- Dead-code sweep: removed the random-access `Ranger` layer, eight unreferenced
  packages, eight `sync2` concurrency primitives, the dormant piece-expiration store and
  `HandlePool`, and seven unreachable files.
- Coverage ratchet in CI with a floor raised to 71%, plus new suites for `sync2`,
  `pkcrypto`, `lrucache`, `encryption`, `base58`, `authorization`, `retain` and
  `process.SaveConfig`.
- `-race` moved off every MR to a nightly job, then restored for MRs once the shutdown
  stalls were fixed; test suite runs once per SHA.
- testplanet: bounded per-planet database connection budget, deterministic
  almost-full-worker and `GetExpired` tests, stop-timeout override set once.
- Repo-wide lint pass: golangci-lint v2, standardized error handling and receiver names,
  fixed slice-aliasing bugs and write-error propagation.
- `docs/test-plan.md` mapped to real tests; rows no test could satisfy were dropped with
  the reason recorded.
- Docs moved into `docs/`; `docs/BRANCHING.md`, `docs/VERSIONING.md` and
  `docs/RELEASE.md` added.
- Self-hosted CI registry, single `CI_BUILDER_IMAGE`, job-token auth for the private
  module graph (no SSH keys), FTP artifact storage with pruning.
