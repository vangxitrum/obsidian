# Release review v0.3.0

**Scope:** whole module at 2523045 (32 packages, ~32k lines), level high. The release covers every commit since the module began, so the review base is the empty tree.

**Verification:** each finding was checked against the code by the reviewing agent, most with a reproduction. Findings 1, 2 and 3 were re-read independently afterwards and hold. Finding 5 was partly re-checked: nothing in `flattenSettings` looks at the `secret` tag. Finding 14 is based on PgBouncer's documented behavior and was not run.

## Findings

### 1. LRU cache grows without bound through `Add`
- **Severity:** major
- **Where:** `lrucache/cache.go:190`
- **Problem:** When the cache is full, `Add` deletes the evicted key from the map but leaves its element in the order list. Every later `Add` then "evicts" that same dead key again, so the cache grows until the process runs out of memory. With Capacity 2, 50 Adds left 49 entries cached.
- **Fix:** Also call `e.order.Remove(item)` when evicting, as the eviction in `Get` already does.

### 2. A publish cut off by a lost channel is reported as a broker NACK and never retried
- **Severity:** major
- **Where:** `rabbitmq/publisher.go:325`
- **Problem:** When a channel closes, amqp091 v1.14 settles every pending confirm as `(false, nil)` (`deferredConfirmations.Close` calls `setAck(false)`), which looks the same as a real NACK. So a broker restart between publish and ack returns "broker nacked" with `retry=false`, and the `Retries` budget never covers the failure it was built for.
- **Fix:** After a `false` ack, check whether the channel is closed (`ch.IsClosed()` or the session context) and treat that as retryable rather than as a NACK.

### 3. Every consumer handler has a hard DrainTimeout deadline, and running past it dead-letters the message
- **Severity:** major
- **Where:** `rabbitmq/consumer.go:292`
- **Problem:** `context2.WithRetimeout` is applied when each handler starts, not only at shutdown. A handler that runs longer than 30s during normal operation gets `DeadlineExceeded`, which misses the `context.Canceled` requeue case, so the message is nacked without requeue: dead-lettered, or dropped if the queue has no dead-letter exchange.
- **Fix:** Apply the drain bound only once shutdown starts, or requeue on `context.DeadlineExceeded` too.

### 4. A slow Graylog blocks all logging, stdout included
- **Severity:** major
- **Where:** `logger/handler.go:117`, `logger/graylog.go:112`
- **Problem:** The Graylog sink does a blocking HTTP POST (5s timeout) for each record, on the single async goroutine that also writes the console. With Graylog slow, 16 of 20 records were dropped and stdout printed about one line per Graylog timeout.
- **Fix:** Give each remote sink its own bounded queue and goroutine, and write to the console and file before handing off to it.

### 5. SaveConfig writes secrets into config.yaml
- **Severity:** major
- **Where:** `config/save.go:210`
- **Problem:** `flattenSettings` writes every viper setting and ignores `secret:"true"` tags, so a password loaded from secrets.yaml (or from the environment) is written live into config.yaml. `db.password: hunter2` came out of secrets.yaml and into the saved config.yaml, which defeats the reason secrets.yaml is kept separate.
- **Fix:** Skip fields tagged `secret` in SaveConfig, or write them only as commented-out empty placeholders.

### 6. `memory.Size.Set` panics on a value made only of letters
- **Severity:** minor
- **Where:** `memory/size.go:165`
- **Problem:** For input such as "MB" or "B", the loop reads `s[p-1]` at index -1 before its `p < 0` guard runs, so a config value like `max-response-size: MB` crashes the process instead of returning an error.
- **Fix:** Loop only while `p > 0 && isLetter(s[p-1])`, and reject an empty numeric part.

### 7. `Add` on a zero-capacity LRU panics
- **Severity:** minor
- **Where:** `lrucache/cache.go:188`
- **Problem:** `Get` treats `Capacity <= 0` as "disabled", but `Add` dereferences `e.order.Back()`, which is nil there.
- **Fix:** Return early from `Add` (and `GetCached`) when `Capacity <= 0`.

### 8. A second `logger.Handler.Shutdown` call panics
- **Severity:** minor
- **Where:** `logger/async.go:100`
- **Problem:** `shutdown` closes the channel without checking whether it is already closed, so the common `defer h.Shutdown(ctx)` plus an explicit call panics with "close of closed channel".
- **Fix:** Guard the close with a closed flag under the lock, or use a `sync.Once`.

### 9. jwt constructors accept the wrong half of a key pair
- **Severity:** minor
- **Where:** `jwt/jwt.go:144`
- **Problem:** `checkKeyType` accepts both the private and public key types for both roles. `NewKeyVerifier(RS256, priv)` succeeds, then every `Verify` fails; `NewKeySigner` also accepts a public key; an ECDSA key on the wrong curve passes too. A mismatch that should fail at startup fails at runtime instead.
- **Fix:** Require public keys in the verifier constructor and private keys in the signer constructor, and check the ECDSA curve against the algorithm.

### 10. A mandatory publish without confirms reports unroutable messages as sent
- **Severity:** minor
- **Where:** `rabbitmq/publisher.go:312`
- **Problem:** With `Mandatory=true` and `Confirms=false`, `publishOnce` returns success before it looks at the return waiter, so an unroutable message is reported as sent although the config help promises it is "returned".
- **Fix:** Wait out the return grace period whenever Mandatory is set, or reject that combination in validation.

### 11. Retries after transport errors are never counted or logged
- **Severity:** minor
- **Where:** `httpclient/retry.go:108`
- **Problem:** The retry metric, the `http_retry` event and the warning log are all inside `if resp != nil`, so retries after a refused or reset connection, the common case during an outage, are invisible.
- **Fix:** Record the retry whenever `loop.Attempt() > 0`, and drain `resp` only when it is non-nil.

### 12. The publisher mutex is held across the socket write
- **Severity:** minor
- **Where:** `rabbitmq/publisher.go:304`
- **Problem:** amqp091 checks the context only before the write, and `pub.mu` is held during it. If the broker blocks the connection (memory or disk alarm), every other `Publish` waits past its deadline, and so do `Stats` (the metrics scrape hangs), `retractChannel` and the return dispatcher.
- **Fix:** Use a dedicated write mutex, separate from the one guarding counters, the channel pointer and return waiters.

### 13. Topology validation allows binding to the default exchange
- **Severity:** minor
- **Where:** `rabbitmq/topology.go:100`
- **Problem:** RabbitMQ refuses `queue.bind` on the default exchange with 403 ACCESS_REFUSED, which Session treats as a broker failure and re-declares forever instead of failing.
- **Fix:** Reject a binding with an empty `Exchange` in `Validate`.

### 14. Startup session parameters break connections through PgBouncer
- **Severity:** minor
- **Where:** `postgres/postgres.go:258`
- **Problem:** `idle_in_transaction_session_timeout` defaults to 60s and is always sent in the startup packet. PgBouncer rejects unknown startup parameters unless listed in `ignore_startup_parameters`, so every connect fails, and with RequireOnStart the service does not boot. Not run against PgBouncer.
- **Fix:** Default the timeout to 0, or add an option to send session settings with `SET` in an `AfterConnect` hook.

### 15. `apierr.With` mutates a shared error in place
- **Severity:** minor
- **Where:** `apierr/apierr.go:86`
- **Problem:** `With` appends to `e.fields` and returns the same pointer. On a package-level sentinel, concurrent requests race on the slice and leak fields into each other's logs.
- **Fix:** Return a copy that carries its own fields slice.

### 16. The debug panel's cycle interface does not match `cycle.Cycle`
- **Severity:** minor
- **Where:** `stats/debug/panel.go:175`
- **Problem:** `CycleController` requires `Restart()`, but the module's own `cycle.Cycle` has `Resume()`, so `debug.Cycle(name, c)` does not compile with the module's own cycle type.
- **Fix:** Rename the interface method to `Resume()`.

### 17. File sink `MaxSize` 0 does not disable rotation
- **Severity:** minor
- **Where:** `logger/file.go:50`
- **Problem:** The docs say 0 disables size-based rotation, but `newFileSink` turns `<= 0` into 100 MB, so rotation cannot be turned off and, with `MaxBackups` set, old logs are deleted without warning.
- **Fix:** Default only when the value is negative and skip rotation at 0, or correct the documentation.

**Verdict:** fix-first - the unbounded LRU growth, the three RabbitMQ message-handling bugs (a lost channel reported as a NACK, handler deadlines dead-lettering messages, the publisher lock) and secrets written into config.yaml are real correctness and security defects in shared library code.
