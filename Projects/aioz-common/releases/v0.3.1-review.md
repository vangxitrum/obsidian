# Release review v0.3.1

Scope: `v0.3.0..HEAD` (`6b79f13` private-network guard, `5343511` retry moved to
the caller), reviewed at high effort. `go build`, `go vet`, `golangci-lint` and
`go test -race ./httpclient/` are clean; the findings are logic gaps the tests do
not reach. Findings 1 and 2 were re-read against the code and confirmed.

**Verdict: fix-first** - finding 1 reopens the double-POST hazard this release
exists to close.

---

## 1. `Idempotency-Key` is checked once, but the request is built every attempt

- **Severity:** medium
- **Where:** `httpclient/retry.go:109` (`if attempt == 0 && !r.replayable(req)`)
- **Problem:** `Retry.Do` decides whether a POST/PATCH may be replayed only on the
  first attempt, from the `Idempotency-Key` header. The docs tell callers to build
  the whole request inside `newRequest`, which runs again for every attempt - so a
  caller who writes `req.Header.Set("Idempotency-Key", uuid.New().String())`
  there sends a fresh key on each retry. A POST that timed out after the server
  had charged the card is retried under a new key, and the server charges again.
- **Fix:** have `Do` require the same `Idempotency-Key` on every attempt (stop
  retrying, or fail, when it changes), and state in the README and godoc that the
  key is created once, outside `newRequest`. Add a test with a key generated per
  attempt.

## 2. The allowlist is not checked against an IPv4 address embedded in NAT64 / 6to4

- **Severity:** low (fails closed)
- **Where:** `httpclient/guard.go:173`
- **Problem:** `blockedAddr` extracts the IPv4 address inside `64:ff9b::/96` and
  `2002::/16` and blocks on it, but the `allowed-networks` loop compares only the
  outer IPv6 address. With `allowed-networks: [10.20.0.0/16]`, a dial to
  `64:ff9b::a14:1` (NAT64 for 10.20.0.1) is blocked and never exempted. It refuses
  rather than admits, so it is not an SSRF hole - it breaks allowed traffic on
  IPv6-only / NAT64 hosts.
- **Fix:** match the allowlist against the same embedded IPv4 address the block
  check used, and add NAT64 and 6to4 cases to the allowlist tests.

## 3. A patch version for a release that removes public API

- **Severity:** low (release process)
- **Where:** `CHANGELOG.md:3`, `.gitlab/releases/v0.3.1.md`
- **Problem:** v0.3.1 removes `WithRetry`, `WithoutRetry`, the `Retry*` config
  fields and their config keys, and makes `NewOneShot` refuse internal addresses.
  A service taking it as a patch fails to compile on `WithRetry` and fails to
  start on the removed keys.
- **Fix:** tag it `v0.4.0` (rename the note and the CHANGELOG heading), or keep
  `v0.3.1` deliberately and say "breaking" in the release title.

---

## Checked and fine

- A refused dial's error still wraps `ErrBlockedAddress` all the way out of
  `Client.Do`.
- A guarded transport disables the proxy, and TLS dials go through the guarded
  dialer.
- `Retry.Do` drains a superseded response before sleeping, and handles a
  cancelled context and a deadline too short for the next wait.
- `AllowedNetworks` binds to empty by default.
- Nothing in the module still references the removed retry API.

## Not raised (outside the diff, or cosmetic)

- `headers.go:16` and `redirect.go:11` comments still mention a "retry layer".
- `ParseRetryAfter` can overflow on an enormous seconds value, which turns the
  wait into an immediate retry. That code is unchanged since v0.3.0.
