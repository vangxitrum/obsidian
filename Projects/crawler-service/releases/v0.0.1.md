## 1. TL;DR

First shippable version of crawler-service: a gRPC data producer that fetches, normalizes,
and republishes hazard, weather, and environmental data from ~30 upstream providers
(earthquake, fire, flood, tropical cyclone, tsunami, volcano, drought, water level,
water scarcity, marine, aviation, tides, air pollution, snow, atmospheric water), backed
by MongoDB/Postgres storage, S3 file snapshots, and RabbitMQ event publishing.

---

## 2. Highlights

### Multi-hazard fetcher framework

- A shared `datafeed.Feed` abstraction (`internal/utils/datafeed`) standardizes how every
  provider fetcher downloads, validates (bodyclose-safe HTTP), and stores raw + parsed
  documents, so each new data source is a thin adapter rather than a bespoke pipeline.
- ~30 fetchers registered in `internal/app/app.go` covering: earthquake (USGS, EMSC, GDACS,
  ShakeMap), fire (FIRMS, Copernicus, GWIS ECMWF/Meteo-France/NASA), flood (GDACS, IFRC
  Alert Hub, MeteoAlarm, NOAA), tropical cyclone (ESRI active hurricanes, GDACS, xWeather),
  tsunami (NOAA), volcano (GVP, VolcanoDiscovery, AviationWeather), drought (USDM), water
  level (ESRI, NOAA, WHOS river gauges), water scarcity, atmospheric water, marine forecast,
  aviation (OpenSky Network), world tides, air pollution (OpenWeatherMap), and snow (AWDB).

### Weather pipeline

- `internal/weatherpipeline` builds Open-Meteo-backed weather layers (grid wind, NOAA
  layers, air quality) into point packs, serves them over gRPC (`open_meteo/grid_wind`)
  with a per-consumer quota, and republishes runs in S3 keyed by a per-series
  current-run pointer so consumers always read a consistent frame.
- Frame and reference cleanup (`weatherpipeline/cleanup*`, `frame_store.go`) reclaims
  stale S3 tiles and MongoDB references on a retention window, independent of the
  standalone cleanup commands below.

### Storage, snapshotting, and eventing

- `internal/utils/store` resolves and dedupes datafeed documents by source + date;
  `internal/utils/filesnapshot` uploads checksum-guarded raw payloads to S3; Postgres
  holds datafeed/datasource state; MongoDB gets native TTL retention for expiring
  collections.
- `internal/utils/producer` + `producer.pb` define the gRPC contract for downstream
  consumers; a RabbitMQ publisher emits per-record events with DLQ/exchange/binding setup
  for replay.

### Operator tooling

- `cmd/app` - the long-running fetch/serve service.
- `cmd/cleanup` - purges crawler-service data from MongoDB and RabbitMQ (never touches
  Postgres).
- `cmd/weather-s3-cleanup` - operator safety-net that deletes immutable weather run
  objects from S3 that the online cleanup missed.
- `cmd/replay` - replays stored events to consumers for a given date range and/or source
  list.

## 3. Added

- **`internal/utils/datafeed`** - shared fetch/store/validate abstraction used by every
  provider fetcher (`feed.go`, ~1069 lines).
- **`internal/aviation/openskynetwork`** - OpenSky Network live aviation fetcher, ported to
  the current `datafeed.Feed` API after rebase.
- **`internal/tropical_cyclone/*`, `internal/gdacs/flood`, `internal/meteoalarm/flood`,
  `internal/noaa_alerts/flood`, `internal/ifrc/alert_hub`** - flood and cyclone incident
  crawlers for GDACS date windows, MeteoAlarm, NOAA alerts, and IFRC.
- **`internal/water_level/{esri,noaa,whos}`** - river gauge datasources across three
  upstream APIs, including WHOS site discovery/client.
- **`internal/water_scarcity`, `internal/atmospheric_water`, `internal/worldtides/tide`,
  `internal/marine_open_meteo/marine_forecast`, `internal/open_weather_map/air_pollution`,
  `internal/awdb/snow`** - additional environmental data fetchers.
- **`internal/earthquake/{usgs,emsc,gdacs,shakemap}`, `internal/fire/*`,
  `internal/volcano/*`, `internal/tsunami/noaa`, `internal/drought/usdm`** - full hazard
  fetcher set (earthquake, fire, volcano, tsunami, drought).
- **`internal/location`** - location store with rotation.
- **`internal/open_meteo/grid_wind`** - gRPC-served grid wind service with a shared quota.
- **`cmd/cleanup`, `cmd/weather-s3-cleanup`, `cmd/replay`** - operator commands (see
  Highlights).
- **`deploy/local`** - local docker dev stack (MongoDB, RabbitMQ, etc.).
- **`.golangci.yml`, `docs/LINTING.md`** - golangci-lint v2 config and long-form linting
  guide, including the `make lint` / `lint-fix` / `lint-new` / `lint-verify` targets.
- **`internal/providercontract`** - contract tests all provider fetchers are run against.

## 4. Changed

- **`internal/utils/datafeed`** - split fetching from storing and collapsed the `Store`
  family down to three methods, so fetchers no longer own their own persistence logic.
- **`internal/utils/store`** - removed `GetLatestDocumentBySourceAndDate` in favor of the
  consolidated resolve-by-source-and-date path.
- **weather pipeline** - the current-run pointer is now keyed by series rather than by
  provider, so multiple providers on the same series no longer clobber each other's
  pointer.
- **`internal/water_level`** - GeoJSON storage now includes date and adjusted pagination
  ordering.

## 5. Fixed

- **flood alerts (IFRC)** - empty polygons are now accepted instead of rejected.
- **logging/shutdown** - double logger shutdown removed; batcher and queue consumer now
  shut down and log cleanly instead of racing or panicking on cancellation.
- **crawler fire (Copernicus)** - fixed a bug in fire crawler.
- **CI lint** - `go-lint` job fixed for `gofmt` and general lint failures.
- **OpenSky config** - excessive logging in production reduced (log level change);
  `G101` false positive silenced with a documented `//nolint`, replacing a blanket ignore
  rule.

## 6. Migration notes

- **Config** - `cmd/app`, `cmd/cleanup`, `cmd/weather-s3-cleanup`, and `cmd/replay` all take
  `-config config.yaml`; ensure the deployed config includes entries for every fetcher this
  release adds (OpenSky, WHOS, IFRC, MeteoAlarm, NOAA alerts, AWDB snow, etc.) before
  rollout, or those fetchers will fail to register.
- **Database** - this is the first release: run the Postgres migration for
  datafeed/datasource state and ensure MongoDB TTL indexes are created before first
  deploy. No migration path from an earlier version exists since there is none.
- **RabbitMQ** - DLQ, exchange, and queue bindings are defined in code on startup; verify
  the broker user has permission to declare them, or pre-declare them out of band.
- **Env/secrets** - `.env` and provider config were removed from git history as part of
  this release; confirm secrets are supplied via the deployment's own secret store before
  first deploy.

## 7. Internal

- Reorganized crawler packages (`refactor: reorganize crawler packages`) into the current
  `internal/<hazard>/<provider>` layout.
- Added `golangci-lint` v2 and fixed all findings it surfaced across the tree.
- Added CI/CD stages and provider contract tests (`internal/providercontract`).
- Added unit and integration test coverage across fetchers, the weather pipeline, the
  batcher, and the queue consumer.
- Bumped/generated protobuf bindings for `producer.pb.go`, `grid_wind.pb.go`, and
  `river_gauge.pb.go`.
