# Release review v0.0.1

Scope: `main..HEAD` (main = empty initial commit; HEAD = `release/v0.0.1`, 119 commits, 309 files). Reviewed at `medium` effort via `/code-review`; all findings below independently re-verified against current code (CONFIRMED).

---

### 1. [CRITICAL] Real OAuth credential committed in plaintext
**File:** `config.docker.yaml:235`
**Problem:** A live-looking OpenSky Network OAuth `client_id`/`client_secret` pair is committed in plaintext. Sibling API configs (e.g. xweather) leave credentials blank instead.
**Fix:** Rotate the OpenSky credential immediately regardless of any other action, remove it from the file, and load it from the deployment's secret store. Rotating alone does not scrub git history - treat the current secret as burned.

### 2. [HIGH] No panic recovery around fetcher goroutines
**File:** `internal/app/app.go:1513`
**Problem:** Each of the ~30 fetchers runs in its own goroutine with no `recover()`, and no `recover()` exists anywhere in production code.
**Fix:** Wrap each fetcher goroutine's entry point in a `recover()` that logs and restarts (or cleanly stops) just that fetcher, so a malformed upstream payload in one source can't take down the whole process, the archiver, weather pipeline, and gRPC server with it.

### 3. [MEDIUM-HIGH] Silent partial-data truncation in ESRI hurricane fetcher
**File:** `internal/tropical_cyclone/esri_active_hurricanes/fetcher.go:192`
**Problem:** `layerQueryURL` builds an ArcGIS FeatureServer query with no `resultOffset`/`resultRecordCount` pagination loop and never checks `exceededTransferLimit`, unlike `internal/water_level/esri/fetcher.go` which paginates correctly.
**Fix:** Port the pagination loop from the water-level ESRI fetcher; check `exceededTransferLimit` and keep paging until it's false, or at minimum log a warning when it's true so truncated hurricane track/wind-field data isn't silently republished as complete.

### 4. [MEDIUM] Transient infra errors dead-lettered same as permanent errors
**File:** `internal/utils/queue/consumer.go:141`
**Problem:** `handleDelivery` always Nacks with `requeue=false` on any handler error, so a transient S3/Mongo blip inside `weatherpipeline.CompletionProcessor.Process` is dead-lettered exactly like a real business-logic error.
**Fix:** Distinguish transient infra errors (network/5xx) from permanent ones and requeue the former, or add limited retry with backoff before dead-lettering.

### 5. [MEDIUM] Duplicate document is still republished on every poll
**File:** `internal/earthquake/shakemap/fetcher.go:248`
**Problem:** `processSingleShakeMapFeature` discards the `inserted` bool from `feed.StoreIfAbsent`, so an already-stored envelope is appended and republished on every poll. `internal/tsunami/noaa/fetcher.go` checks this bool correctly and skips republishing.
**Fix:** Check `inserted` and skip `PublishBatchWithEventID` when the document already existed, matching the tsunami fetcher's pattern.

### 6. [MEDIUM] Station data stored but never published on downstream failure
**File:** `internal/awdb/snow/fetcher.go:65`
**Problem:** `fetch()` stores per-state station documents via `fetchStations` before three separate early-return error paths (empty triplets, `fetchData` failure, empty `dataDocs`), all of which skip the final `PublishBatch` call.
**Fix:** Either publish stations independently right after storing them, or move the store to after all fetch stages succeed so store and publish stay consistent.

### 7. [MEDIUM] Publisher never closed on shutdown
**File:** `internal/app/app.go:185`
**Problem:** The `queue.Publisher` created in `App.New()` is kept only in a local variable, never assigned to the `App` struct, and `Publisher.Close()` is never called during shutdown - unlike `cmd/replay/main.go` and `cmd/cleanup/main.go`, which both `defer Close()`.
**Fix:** Store the publisher on `App` and close it in the shutdown path alongside the gRPC `GracefulStop`.

### 8. [LOW-MEDIUM] Archiver has no default for zero timeout
**File:** `internal/utils/archiver/archiver.go:69`
**Problem:** `context.WithTimeout(ctx, a.cfg.Timeout)` has no fallback when `Config.Timeout` is zero, unlike `queue.Config`, which defaults `ReconnectWait` when `<= 0`.
**Fix:** Apply a sane default (e.g. same pattern as `queue.Config`) when `Timeout <= 0`, so a missing config key fails loudly at load time instead of silently deadline-exceeding every archive run.

### 9. [LOW-MEDIUM] Archiver no longer guards the zero-document case
**File:** `internal/utils/archiver/archiver.go:98`
**Problem:** `ArchiveSources` no longer checks whether a source's stream produced any documents before starting the S3 upload. The deleted `internal/pkg/archiver/archiver.go` had an explicit zero-doc guard that aborted the upload; there's no equivalent now.
**Fix:** Re-add the empty-stream guard so a trigger with nothing pending doesn't upload and log a near-empty `.ndjson.gz` object as a successful archive.

### 10. [LOW] Parse failures invisible to feed health metrics
**File:** `internal/tsunami/noaa/fetcher.go:160`
**Problem:** `fetchEndpoint` returns a bare error on CAP-parse failure without calling `f.feed.RecordFailure`, unlike `internal/earthquake/shakemap/fetcher.go`, which does record a failure on its own decode error.
**Fix:** Call `f.feed.RecordFailure` on the parse-failure path so a feed that's parsing garbage every poll doesn't show healthy in `Up`/`ConsecutiveErrors`/`TotalFailure` metrics.

### Noted but not ranked (lower severity / currently latent)

- `internal/aviation/openskynetwork/oauth.go:77` - unbounded `io.ReadAll` on the OAuth token response, bypassing the datafeed layer's size cap.
- `internal/aviation/openskynetwork/oauth.go:25` - unsynchronized token cache; currently safe only because each fetcher runs single-goroutine.
- `pkg/lrucache/cache.go` `Add()` - latent nil-pointer panic when `Capacity <= 0`; unreachable with current call sites (all default to positive capacity).
- Commits `517023b`, `e1336be`, `ca25ac1` carry `Co-Authored-By: Claude ...` trailers - against this project's own commit-message convention (message content only, no trailers). Worth a history note; not a release blocker on its own.

---

## Verdict: **fix-first**

Finding #1 (plaintext OAuth secret) must be rotated and removed before this is tagged and deployed - that alone blocks shipping as-is. #2 (no panic recovery) and #3 (silent partial hurricane data) are strongly recommended before release given blast radius; #4-#10 can ship with follow-up tickets if the team accepts the risk, but should not be silently dropped.
