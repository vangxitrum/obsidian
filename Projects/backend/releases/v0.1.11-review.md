# Release review v0.1.11

Range `v0.1.10..HEAD` (50 commits, 92 files). 8 finder angles → verified.

**Verdict: FIX-FIRST.** Two release-blocking defects remain (#1, #4). #2 (earthquake watermark) is **FIXED** in commit `3f16e356`.

---

## Blocking

### 1. `air_pollution` poller ingests nothing on a default deploy — `Burst=0`
- `internal/config/config.go:268,279` — sets `air_pollution.enabled=true` and `air_pollution.rps=0.5` but **no `air_pollution.burst` default**. Sibling `open_weather_map` sets `burst=2`.
- `internal/datasource/datasource/datasource.go:128` — `rate.NewLimiter(rate.Limit(0.5), 0)`; no burst clamp.
- **Failure:** on any fresh deployment (no DB datasource row), every air-pollution fetch calls `limiter.Wait(ctx)` → `"rate: Wait(n=1) exceeds limiter's burst 0"` immediately. All 100 locations error every cycle; zero records ingested.
- **Fix:** add `v.SetDefault("air_pollution.burst", 2)` (also set `interval`/`timeout`).

### 2. `usgs_earthquake` never migrated to an event-date watermark — late-reviewed quakes still missed — ✅ FIXED (`3f16e356`)
- Was: `store.go` `LatestFetch` = `MAX(fetched_at)` fed to the USGS `starttime` **event-origin-time** query bound. `fetched_at` advances to ~now each run, so `starttime` = last-run date; an event whose origin time precedes the last run but is published later falls outside `[starttime, end]` and is never fetched — the exact "missing record" class the release claims to fix everywhere else.
- **Fix:** added `Store.LatestEventDate()` = `MAX("time")`; the query window now starts at `backfillStart(latestEvent)` = event watermark − 30-day `eventRevisionLag`, clamped to the cold-start floor. `MAX(fetched_at)` is now used only to throttle poll frequency. Regression tests `Test_backfillStart_*` guard it.

### 3. `usgs_earthquake` re-fires tsunami outbox notifications on every warm poll
- `internal/datasource/usgs_earthquake/earthquake/service.go:62-70` — after `Upsert`, loops **all** records with `Tsunami==1` and calls `saveToOutbox` unconditionally. No newly-inserted / `RowsAffected` check (the old in-memory "only new events" filter was removed).
- **Failure:** a tsunami event stays in the ~1-2 day re-scan window and re-emits an outbox entry every poll interval until it ages out. Upsert dedups the DB row; the outbox does not. Same class as the documented co2/ch4 "re-save-all spams the outbox" gotcha.

### 4. `awdb/snow_cover` — lagged/revised observations permanently dropped (the class this PR claims to fix)
- `internal/datasource/awdb/snow_cover/fetcher.go:100-104` — `backfillBeginDate = MAX(date) + 1 day`, no overlap, stored via plain `Store.Create` (`store.go:38`, no Upsert).
- **Failure:** station A reports through day 10, station B lags and later publishes days 6-10. `MAX(date)=10` → `beginDate=11`, so B's days 6-10 (< 11) are never fetched. Every sibling added overlap lag (arcgis 7d, nasa 30d, usdm 14d) + Upsert; awdb did neither.

## Should-fix

### 5. `relief_web/conflict_news` over-polls every tick — throttle guard fed an event date
- `internal/datasource/relief_web/conflict_news/fetcher.go:313,322` — `latestTime` now comes from `LatestPublished` (`MAX(published_at)`, event date) yet still feeds the throttle `if now.Sub(latestTime) <= Interval`. ReliefWeb has ~1-day publish latency, so the guard is always false → full multi-category paginated re-fetch every tick and every restart. Siblings kept a separate `LatestFetch()` for this guard.

### 6. `currentweather` (and `airpollution`) DTO rejects coordinate 0
- `internal/api/currentweather/dto.go:4-5` — `Lat/Lng float64 binding:"required,..."`. go-playground `required` fails on zero value → `lat=0` (equator) or `lng=0` (prime meridian) return 400. The marine `LookupRequest` in this same release explicitly uses `*float64` to avoid exactly this. Use pointer floats.

### 7. Upstream OWM status + body leaked to API clients
- `internal/datasource/open_weather_map/current_weather/service.go` — non-200 from OWM returned verbatim via `NewHTTPError(resp.StatusCode, string(body))`. An expired server API key → client gets `401 Unauthorized` + OWM's raw JSON instead of a `502`. (`marine_forecast/endpoint.go` Lookup has the same pattern, lower severity — no API key.)

### 8. `GetByCoords` / `GetLatestByCoords` scan the records table and pick the closest *record*, not location
- `forecast/store.go:135`, `air_pollution/store.go:139` — haversine `Order("distance").Limit(1)` runs over `owm_*_records JOIN state_provinces`, computing trig for every record row. Two costs: (a) degrades linearly as history grows (forecast ≈ 40 rows/loc/fetch); (b) a location with zero stored records is invisible, so a nearer-but-unfetched province is silently skipped for a farther one. Fix: resolve nearest from `state_provinces` alone, then query records by id.

## Also noted (lower confidence / likely intended)
- **v1 layer catalog:** on a default (`map_version=v1`) deploy, `/weather/map/layers` lists no OWM layer with `Available:true` (all 5 v1 layers are `continue`d as superseded; v2 emitted with `Available:false`). Baked into `layers_merge_test.go`, so likely intended — but a v1 server can still serve those tiles, so the FE would show none. Confirm intended.
- **grib forecast layers:** merged layers expose `HasForecast:true, MaxForecastDays:14` but their tile URL has no `?day=` param, so only the today-snapshot is reachable through the unified catalog.
- **nsidc_sii / arcgis:** `nsidc` strict-after + no-overlap + plain Create drops in-place revisions of the newest stored day; `arcgis/chokepoints` offset paging on non-unique `Date DESC` can skip a boundary row within a poll (add `ObjectId` tiebreaker).
- **`state_province_id` NULLable** but column 1 of the unique index → NULLs bypass `ON CONFLICT`, accumulating duplicate rows if any coord-only record is ever inserted.
- **Duplicated store SQL** between `forecast/store.go` and `air_pollution/store.go` (haversine + oldest-fetched-first blocks) — extract a shared helper.

Clean and correct: ucdp, usdm, nasa_coolr, noaa_gml (n2o/co2/ch4/sf6) watermark logic; HTTP bodies closed via `io.LimitReader`; migrations `public.`-qualified with correct down-reversal and no N+1 upserts.
